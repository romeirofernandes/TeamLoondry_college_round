# Voice diagnosis and verification

The earlier default selected on-device browser speech. Chrome needs both the experimental local speech API and an installed pack for the chosen language. A clean profile without that pack could never start listening. The exact phrase parser also rejected polite or multilingual commands even when transcription succeeded. These are separate failures, so a microphone indicator alone did not prove commands were working.

The adapter regression test reproduces the first failure by returning `downloadable` from Chrome's language availability check. Explicit local mode still refuses to send audio to a remote service. Browser speech is now the default, with a visible audio notice, and the offscreen capture layer can use the separately configured Groq transcription fallback. The adapter reports permission, microphone, network, and language failures so the controller can offer a retry.

`SpeechAdapter` now displays interim transcripts through a separate callback. Only final results reach command processing. Pause, stop, recognition errors, and recognition end clear the interim text. Generation checks reject late callbacks. Language tags are canonical BCP47 values, such as `en-IN` and `hi-IN`. Automatic browser speech uses the browser locale; automatic Groq transcription omits the language hint.

Ordinary command phrases go to Jev through the [OpenRouter Decisions API](https://openrouter.ai/blog/tutorials/how-to-use-jev/) or the [TypeSafe HTTP API](https://docs.typesafe.ai/api). Jev chooses from existing browser commands. Handsfree checks the selected action, its probability, and a separate direct-request judgment before dispatching it. Ambiguous speech becomes an unknown command. Exact emergency commands remain available immediately. Without a Jev key, the exact phrase parser still works.

Jev chooses among supplied values and does not generate strings. Search queries, numbered selections, and named tabs retain arguments only when the exact parser already extracted them. Arbitrary requests use the separate "hey handsfree" route. Groq's [Qwen model](https://console.groq.com/docs/model/qwen/qwen3.8-27b) returns a validated browser intent or IDs from the visible target list. Unknown IDs, code, unsupported commands, and combined intent-plus-ID responses are rejected. Existing confirmation and activation checks still apply after provider mapping.

[Groq speech transcription](https://console.groq.com/docs/speech-to-text) uses `whisper-large-v3-turbo`. It uploads an audio chunk, never the webcam feed. Language hints use two-letter codes, so `hi-IN` becomes `hi`. Silence metadata suppresses transcripts when every returned segment reports a high no-speech probability. This helps with silence hallucinations but cannot eliminate noise errors. Five configured Groq keys rotate through a serialized index reservation shared by command and transcription requests. A rate limit produces an error, without retrying across other keys.

Cloud disclosure must distinguish the data involved. Browser speech may send microphone audio to the browser vendor. Groq fallback sends microphone chunks to Groq. Jev receives final command text and the selected language. Arbitrary Groq commands receive the final command and visible element labels. Dictated text bypasses command mapping. No provider receives camera frames from these helpers.

Verification completed at the provider and speech-adapter boundaries with deterministic tests for interim/final separation, unavailable local packs, late callbacks, multilingual locales, finite action validation, invalid IDs, aborts, silence metadata, and concurrent key rotation. A live OpenRouter Jev request mapped "move a bit further down" to scrolling down and "Please click the button I am pointing at" to clicking. "I really like this blue colour" remained an unknown command. Credentials were read only from the ignored local configuration and were not logged.

To check actual audio, reload the unpacked extension after rebuilding, open a normal website, start Handsfree, and allow the microphone. First watch for an interim transcript. Then say "scroll down" and a polite alternative such as "move a bit further down". Switch to Hindi and repeat a scroll command. Use "hey handsfree" for the arbitrary route. In a focused input, say "start typing", dictate literal text, then say "stop typing". Deny the microphone once and confirm that the controller gives an error and a retry action. Finally pause or stop and confirm that no late transcript executes. Real microphone accuracy, Chrome speech service availability, and each selected language still need this browser check; unit tests do not measure them.
